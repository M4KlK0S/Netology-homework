## Подготовительный этап 1. Создание и копирование публичного SSH-ключа

Публичный ключ нужен для доступа к виртуальной машине по SSH.

**1. Откройте powershell**

Нажмите Win + X и выберите Windows powershell или Терминал.

**2. Сгенерируйте ключ**

Выполните команду:
```powershell
ssh-keygen -t ed25519
```
Система задаст три вопроса:
- Место сохранения — нажмите Enter (путь по умолчанию).
- Пароль — нажмите Enter дважды (без пароля).
- Подтверждение пароля — ещё раз Enter.

После этого в папке C:\Users\Win 10 Gigabyte\.ssh\ появятся два файла: id_ed25519 (закрытый ключ) и id_ed25519.pub (публичный ключ).

**3. Скопируйте публичный ключ в буфер обмена**
```powershell
cat ~/.ssh/id_ed25519.pub | clip
```
Команда | clip копирует содержимое файла в буфер обмена. Ключ готов к вставке.

> [!IMPORTANT]
> копируйте только файл с расширением .pub. Файл без расширения — закрытый ключ, его нельзя передавать.

## Подготовительный этап 2. Создание сервисного аккаунта с ролью monitoring.editor

Сервисный аккаунт нужен, чтобы агент сбора метрик на ВМ мог отправлять данные в Yandex Monitoring.

**1. Перейдите в Identity and Access Management**

В консоли управления Yandex Cloud выберите нужный каталог, затем в левом меню найдите Identity and Access Management.

**2. Нажмите «Создать сервисный аккаунт»**

Кнопка расположена в правом верхнем углу.

**3. Задайте имя**

Имя должно содержать только строчные латинские буквы, цифры и дефисы, начинаться с буквы, длина — от 3 до 63 символов. Например: monitoring-sa.

**4. Добавьте роль monitoring.editor**
- Нажмите кнопку Добавить роль (знак «плюс»).
- В списке найдите monitoring.editor (можно использовать поиск).
- Нажмите на роль, чтобы выбрать её.

**5. Создайте аккаунт**

Нажмите Создать. Аккаунт появится в списке и станет доступен для выбора в разделе «Доступ» при создании ВМ.

## Задание 1. Создание виртуальной машины и дашборда

**Часть A. Создание виртуальной машины**

1. В консоли Yandex Cloud перейдите: Все сервисы → Инфраструктура и сеть → Compute Cloud.
2. Нажмите синюю кнопку Создать ВМ в правом верхнем углу.
3. Задайте параметры ВМ согласно заданию:

| Параметр | Значение |
|---|---|
| Имя | Любое на английском (например, `task-vm`) |
| Операционная система | Debian 11 |
| Объём HDD | 3 ГБ |
| Платформа | Intel Ice Lake |
| Количество vCPU | 2 |
| Гарантированная доля vCPU | 20% |
| RAM | 1 ГБ |
| Прерываемая | Поставить галочку |

4. В разделе Доступ выберите созданный ранее сервисный аккаунт monitoring-sa с ролью monitoring.editor.
5. Задайте логин учётной записи ВМ (например, user).
6. В поле SSH-ключ вставьте публичный ключ из буфера обмена (начинается с ssh-ed25519).
7. Поставьте галочку «Установить» в пункте «Агент сбора метрик» — выберите Yandex Monitoring .
8. Нажмите Создать ВМ. Дождитесь статуса RUNNING.

## Часть B. Создание дашборда в Monitoring

1. Перейдите: Все сервисы → Инфраструктура и сеть → Monitoring.
2. На главной странице сервиса нажмите Создать дашборд .
3. В разделе «Добавить виджет» нажмите «График».
4. В конструкторе запросов выберите «Запрос А».
5. В параметре service выберите Compute Cloud.
6. В появившемся параметре name выберите cpu_utilization.
7. Поправьте диапазон времени: нажмите кнопку «Сейчас» вверху экрана (левее кнопок 3m, 1h, 1d, 1w).
8. Нажмите «Сохранить» в правом верхнем углу.
9. Введите имя дашборда (например, CPU Dashboard) и нажмите Сохранить.

## Задание 2. Создание алертов WARN и ALARM с уведомлением по e-mail

1. Создайте канал уведомлений (если его нет)
- В Monitoring на панели слева выберите Каналы уведомлений.
- Нажмите Создать канал.
- Укажите имя (например, email-alerts).
- В поле Метод выберите Email.
- В поле Получатели укажите ваш e-mail.
- Нажмите Создать.

2. Создайте первый алерт (WARN)
- На главной странице Monitoring нажмите Создать алерт .
-  Задайте Название (например, CPU WARN).

В блоке запроса укажите:
  - service = compute
  - name = cpu_utilization

В блоке Условия срабатывания:
  - Функция агрегации: Avg (или Max — на ваш выбор).
  - Функция сравнения: Больше.
  - Порог Warning: 70 (или другое значение на ваш выбор).
  - Порог Alarm: оставьте пустым или укажите 90 (если хотите, чтобы этот алерт срабатывал только на WARN, настройте отдельно).
  - Окно вычисления: 5m (5 минут).

В блоке Уведомления выберите созданный канал email-alerts.
- Нажмите Создать.

3. Создайте второй алерт (ALARM)
- Снова нажмите Создать алерт.
- Задайте Название (например, CPU ALARM).
- Укажите те же параметры запроса: service = compute, name = cpu_utilization.

В блоке Условия срабатывания:
- Функция агрегации: Avg.
- Функция сравнения: Больше.
- Порог Warning: оставьте пустым.
- Порог Alarm: 90 (или выше, чем WARN).
- Окно вычисления: 5m.

Выберите тот же канал уведомлений email-alerts.

Нажмите Создать.

Теперь при загрузке CPU выше 70% сработает WARN, а выше 90% — ALARM. Уведомления будут приходить на указанный e-mail.
